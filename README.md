# 증강 오목 v0.4 — 온라인 2인용

기존 증강 오목 v0.3을 유지하면서 **방 코드 접속, 실시간 대국, 증강 선택·효과 동기화**를 추가한 데모입니다.

## 설치 및 로컬 실행

- **Node.js 18 이상**이 필요합니다. (권장: LTS)
- 다른 npm 패키지는 필요하지 않습니다. `npm install`도 생략 가능합니다.

Windows는 `start_windows.bat`를 더블클릭하거나, 터미널에서 다음을 실행하세요.

```bash
npm start
```

브라우저에서 **http://localhost:3000** 에 접속합니다.

1. 흑 플레이어가 **새 대국 방 만들기**를 누릅니다.
2. 화면에 나타나는 6자리 방 코드 또는 **초대 링크 복사**로 친구에게 공유합니다.
3. 친구는 동일한 서버 주소로 접속하여 코드 입력 또는 링크로 입장합니다. 친구는 **백**입니다.
4. 양쪽이 접속하면 대국이 시작됩니다. 10·30·50수 직후 **흑부터 백 순으로** 각자의 후보 3개 중 증강 1개씩을 선택합니다.
5. 자신의 차례에 돌을 두거나 보유한 증강을 사용합니다. 상대 증강과 쿨타임은 모두 공개됩니다.

**주의: HTML 파일만 친구에게 보내는 것으로는 멀티플레이가 되지 않습니다. 두 사람이 동일한 게임 서버에 접속해야 합니다.**

## 친구와 실제로 접속하는 방법

### 같은 와이파이 / 같은 LAN

1. 서버를 실행한 PC에서 `ipconfig`(Windows) 또는 `ip addr`(macOS/Linux는 `ifconfig`)로 내부 IP를 확인합니다.
2. 호스트는 `http://localhost:3000`으로 접속합니다.
3. 친구는 **같은 네트워크**에서 `http://호스트의-내부IP:3000`에 접속합니다. 예: `http://192.168.0.12:3000`.
4. 방을 만들고 코드를 보내세요.
5. 접근이 안 되면 서버 PC의 방화벽에서 Node.js TCP 포트 3000 인바운드를 **사설 네트워크에 한해** 허용해야 할 수 있습니다.

### 다른 장소 / 다른 네트워크에서 (추천: Render)

1. 압축을 해제하고, **프로젝트 폴더 안 파일들을 GitHub 저장소의 루트에 업로드**합니다. (`server.js`, `gameEngine.js`, `public/`, `package.json` 등이 저장소 최상위에 보여야 합니다.)
2. [Render](https://dashboard.render.com/) → **New** → **Web Service** → GitHub 저장소 연결.
3. `Language: Node`, `Build Command: npm install`, `Start Command: npm start`, `Instance Type: Free`로 설정합니다. `Root Directory`는 저장소 최상위면 비워둡니다. (포함된 `render.yaml`을 사용해 Blueprint로 배포해도 됩니다.)
4. 배포가 끝나면 부여받은 `https://...onrender.com` 링크에 접속합니다.
5. 이 **공개 URL**에서 방을 만들고 초대 링크를 친구에게 보내면, 서로 다른 네트워크의 PC에서도 대국할 수 있습니다.

Render 무료 서비스는 장시간 유휴 상태일 때 중지되거나 재시작될 수 있습니다. **게임 상태를 서버 메모리에만 저장하므로 서버가 재시작되면 진행 중인 대국과 방이 사라집니다.** 장기적으로 게임을 보존하려면 Redis/DB 저장 기능이 필요합니다.

## 포함 기능

- 15×15 교차점, 흑 선공, 5목 승리 판정 (흑은 정확히 5, 백은 5 이상)
- 흑 쌍삼·사사·장목 금수 기본 판정 (v0.3에서 사용하던 휴리스틱; 복잡한 예외 규칙은 추가 검증 필요)
- 영구 보유 증강 7종: 등가교환, 기사의 도약, 한 칸 전진, 공간 도약, 잔해 수집, 금기의 해방(흑 전용), 포위의 한 수
- 10·30·50수마다 개인별 3개 중 1개 선택 (후보는 본인만 열람 가능)
- 증강 사용 시 **일반 착수 대신 한 턴 소비**, 각자 턴 기준 쿨타임
- 서버가 착수, 금수, 증강, 쿨타임, 선택 후보를 검증. 클라이언트가 임의 상태를 보낼 수 없음
- 흑·백 접속 상태, 서버 연결 표시, 브라우저 새로고침 후 토큰 자동 복귀 (브라우저 localStorage)
- 무르기와 새 대국은 **상대 동의 후** 수행
- 제3자는 이미 2명이 들어간 방에 입장 불가 (관전 기능 미제공)
- 로그인, DB, 별도 npm 패키지 불필요

## 제한 사항

- 현재는 개발용 데모입니다. 자동 매칭, 계정, 관전, 영구 저장, 접속 종료로 인한 자동 몰수, 서버 다중 인스턴스 동기화는 없습니다.
- 6자리 코드는 방 조회 수단이지 개인정보 보호용 비밀번호는 아닙니다. 신뢰하는 친구에게만 코드를 공유하세요.
- 임시 개인 토큰을 같은 브라우저의 저장소에 보관하므로 같은 프로필에서 중복 탭을 열면 같은 플레이어로 접속할 수 있습니다. 한 PC에서 두 역할을 테스트하려면 다른 브라우저 프로필 또는 시크릿 창을 사용하세요.
- 클라이언트는 SSE(Server-Sent Events)로 게임 상태를 수신하고 HTTP POST로 입력을 서버에 전송합니다. WebSocket 대신 Node.js 표준 라이브러리만 사용하는 실시간 통신 방식입니다.
